# ДЖУРА

Русскоязычная мастерская однотипных Word-документов. Vue 3 + TypeScript, без backend, аккаунтов и передачи пользовательских документов на сервер.

## Возможности

- DOCX с `{{полями}}`, включая плейсхолдеры, разбитые Word на несколько runs; одинаковые поля объединяются.
- Визуальная разметка точного текстового представления DOCX: выделение внутри абзаца/ячейки, подсветка, явное добавление повторных вхождений.
- Текст, многострочный текст, дата, число, обязательность и форматирование.
- Единая таблица: ручной ввод, XLSX/CSV, сопоставление колонок, листы XLSX, Ctrl+V диапазонов, дублирование, удаление, виртуализация.
- Проверка строк, исключения, предпросмотр любой строки, безопасные уникальные имена, DOCX или ZIP, CSV-отчёт частичных ошибок.
- Массовая замена в DOCX/ZIP, регистр, целые слова, основной текст/таблицы/колонтитулы; режим однотипных документов с явными полями.
- Шаблоны в IndexedDB, переносимый `.dzhura` v1, черновики создания и изменения, четыре локально сохраняемые палитры, подробный гайд.
- Обработка в Worker с отменой. Оригиналы не изменяются.

## Запуск

Node.js 24 LTS и npm. В Windows PowerShell при запрете `npm.ps1` используйте `npm.cmd` / `npx.cmd`.

```sh
npm ci
npm run dev
```

Откройте адрес из терминала (обычно http://127.0.0.1:5173).

```sh
npm run build
npm run preview
```

`dist/` — готовые статические файлы. На production Node.js не требуется. Настройки подключения и секреты отсутствуют, `.env` не нужен. Приложение рассчитано на корень домена или отдельный поддомен.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run fixtures
npx playwright install chromium
npm run build
npm run test:e2e
npm run benchmark
npm audit
```

Playwright запускает **production preview**, а не dev-сервер. Можно использовать установленный Edge: `$env:PLAYWRIGHT_CHANNEL='msedge'` в PowerShell. На Linux/macOS: `PLAYWRIGHT_CHANNEL=msedge npm run test:e2e` при установленном браузере.

Fixtures лежат в `tests/fixtures`: `contract.docx` (разбитые runs, повторы, таблица, колонтитул), `plain.docx` (визуальное поле), `data.xlsx`, `data.csv`, `batch.zip`, `corrupt.docx`. Это настоящие файлы форматов, а не имитация обработки.

Для ручной проверки загрузите `contract.docx`, пройдите поля, импортируйте `data.xlsx`, откройте предпросмотр второй строки и скачайте ZIP. Для визуального поля используйте `plain.docx`. Проверьте скачанные файлы в вашей версии Word/LibreOffice перед использованием в рабочем процессе.

## Архитектура

```text
src/app                 router, runtime Pinia session, theme tokens
src/pages               пользовательские сценарии
src/features            поля, таблица, импорт, preview, библиотека и задания
src/domain              модели, валидация, форматирование, контракты, лимиты
src/infrastructure
  docx                  XML parser/index/replacer/engine, безопасный preview source
  spreadsheet           ExcelJS + PapaParse, mapping
  archive               ограниченная распаковка, ZIP, .dzhura + Zod schema
  persistence           IndexedDB через idb
  processing            LocalProcessingProvider
src/workers             типизированные задачи и dispatcher
src/shared              UI, файлы, сериализация Vue-состояния
```

`DocumentEngine` не зависит от Vue. Для другого формата реализуйте его контракт и добавьте задачи, не меняя таблицу и валидацию. PDF сейчас не реализован.

`ProcessingProvider` — асинхронный типизированный порт. `LocalProcessingProvider` создаёт Worker для операции, передаёт прогресс, прекращает Worker при отмене и ошибке. Будущий remote-provider может реализовать этот же контракт; сетевой код, Go и PostgreSQL сейчас отсутствуют.

DOCX остаётся ZIP с OOXML. Индекс связывает part + paragraph + диапазон символов с `w:t`. Замены идут справа налево; значение получает стиль первого run. Многострочные значения создают `w:br`, табуляция — `w:tab`. HTML не используется для генерации DOCX.

## Приватность и хранение

Нет аналитики, error-reporting, внешних шрифтов и API. Production CSP запрещает `connect-src`; worker, JS и шрифты загружаются с самого сайта. Предпросмотр в sandbox iframe; внешние relationships удаляются из отдельной preview-копии **до** рендеринга. Генерируемый DOCX сохраняет исходные отношения, в том числе обычные ссылки.

IndexedDB содержит только явно сохранённые шаблоны и не более одного черновика для каждого из двух сценариев. Черновик старше 30 дней удаляется при чтении; успешная генерация его очищает. Результаты не записываются в базу. Нет скрытых бесконечных версий. Очистка данных сайта удалит локальное сохранение; `.dzhura` — резервная копия с оригинальным DOCX внутри. Ошибка/квота IndexedDB показывается пользователю, не подменяется ложным «сохранено».

Local-first не означает офлайн-PWA: для первого открытия, обновления и ещё не загруженных разделов нужен сайт. Service worker отсутствует.

## Совместимость и ограничения

- Поддерживается обычный Transitional OOXML DOCX. DOC, DOCM, PDF, шифрование, ZIP64/многотомные ZIP и Strict OOXML отвергаются с сообщением.
- Текст сносков, text boxes, вложенных объектов и сложных конструкций не редактируется. Абзацы с tracked changes, полями Word, drawing/object, content controls защищены. Содержимое сохраняется, о пропусках сообщается.
- Визуальная разметка работает в точном текстовом представлении; постраничный `docx-preview` — отдельная read-only вкладка. Это сознательное ограничение: разметка по приблизительной HTML-геометрии без надёжной связи с OOXML может менять не то вхождение.
- Визуальное поле не пересекает абзацы, табуляцию и существующий разрыв строки. Нельзя накладывать поля друг на друга.
- Браузерный preview не гарантирует пиксельного совпадения и пагинации Word. Сложный документ проверяйте в Word. Автоматического склонения имён, вычисления формул и сумм прописью нет.
- CSV: UTF-8, заголовки в первой строке. XLSX: сохранённые значения формул, без их исполнения. Идентификаторы храните текстом, даты CSV — ISO.
- Объём входного файла/пачки ограничен 128 МиБ, распакованного ZIP — 256 МиБ и 10 000 записей. Эти пределы защищают от archive bombs и расхода памяти, а не ограничивают тариф.
- После benchmark ограничено удержание готовых DOCX в одном задании: 64 МиБ. Уже готовые документы остаются доступны, остальные перечисляются в отчёте. Лимиты задаются в `domain/limits.ts` и `archive/safe-zip.ts`; предупреждение начинается со 100 строк. Большие изображения существенно меняют потребление памяти.
- Измерения Node в `docs/benchmark.json` — синтетический baseline, не гарантия для браузеров/устройств. Браузерные сценарии отдельно проверяются Playwright.

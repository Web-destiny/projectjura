# ДЖУРА на GitHub Pages

GitHub Pages подходит для ДЖУРЫ: приложение собирается в статические файлы и обрабатывает документы в браузере. После публикации другу достаточно открыть ссылку; компьютер автора проекта может быть выключен. Загруженные документы и локальные шаблоны не попадают в репозиторий или на GitHub Pages. Они остаются в браузере пользователя, поэтому у каждого свой набор шаблонов и черновиков.

1. Создайте репозиторий на GitHub, например `dzhura`. Для GitHub Free с Pages используйте публичный репозиторий. На GitHub Pro Pages доступен и из приватного репозитория, но сам сайт всё равно публичен. Не добавляйте в репозиторий реальные документы или персональные данные.
2. Загрузите исходники проекта в ветку `main` вместе с `.github/workflows/pages.yml`. Папки `node_modules`, `dist` и `test-results` исключены через `.gitignore`.
3. В репозитории откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.
4. Дождитесь успешного выполнения workflow **Publish to GitHub Pages** в разделе **Actions**. Ссылка появится в настройках Pages и в результате workflow. Для обычного репозитория она выглядит как `https://USERNAME.github.io/REPO/`.
5. Откройте ссылку, проверьте создание документа и обновление страницы на `/create` и `/guide`. На GitHub Pages прямой переход на внутреннюю страницу технически отдаёт `404.html` со статусом 404, но копия приложения открывает нужный экран; навигация внутри сайта работает обычно.

Workflow сам подставляет путь репозитория в Vite и Vue Router. Если репозиторий называется `USERNAME.github.io`, сайт собирается для корня домена. Для собственного домена потребуется собрать приложение с `GITHUB_PAGES_BASE=/` и отдельно настроить домен в GitHub Pages.

GitHub Pages не применяет файлы `_headers` и `_redirects` этого проекта. Для размещения с серверными заголовками безопасности и полноценным SPA fallback используйте хостинг из [DEPLOYMENT.md](DEPLOYMENT.md).
